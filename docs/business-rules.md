# 业务规则

- 订单以（租户, 订单标识）唯一；重复受理必须被拒绝且不改变已存在单据。
- 未收金额 = 订单金额 − 已收金额；收款不得超过未收金额。
- 跨租户读取一律按“不存在”处理，不得泄漏对象是否存在。
- 金额以最小货币单位的整数表示，不使用浮点数。

## 收款

- 每笔登记的收款在登记时生成订单内唯一的收款标识，并在响应中返回，调用方据此点名冲正。
- 收款随登记落明细（`payments`）；已收金额恒等于未被冲正的收款明细合计。

## 冲正

- 冲正由调用方指定冲正标识（订单内唯一）与被冲正收款标识；冲正记录保留原收款金额、冲正标识、被冲正收款标识，便于事后核对。
- 一次冲正只影响被点名的那一笔收款，不影响同订单的其他收款。
- 冲正成功后订单回到“受理中（accepted）”，可继续登记收款；再次收满时状态回到“已结算（settled）”。
- 幂等：同一冲正标识配合同一收款标识重复请求，返回与首次一致的结果且不重复扣减；同一冲正标识指向另一笔收款属于冲突，必须拒绝。
- 拒绝情形须可区分，且不得改变订单与收款状态：
  - 收款不存在（含跨租户点名、订单不存在）：按不存在处理，不泄漏对象是否存在；
  - 收款此前已被冲正：拒绝重复冲正；
  - 冲正标识已用于另一笔收款：拒绝冲突。
- 并发登记收款与并发冲正同一订单时，写操作在单事务内串行完成、失败整笔回滚：已收金额始终不超过订单金额且不为负，不允许出现半笔生效的收款或冲正。
- 收款与冲正持久化保存，服务重启后按原结果重放查询；已收与未收金额之和始终等于订单金额。

## 批量导入收款

- 一次提交携带调用方指定的批次号 `batch_id` 与一份待登记收款清单；每行给出订单标识、收款金额与本批内唯一的行内序号 `line_no`（正整数）。`(租户, batch_id, line_no)` 共同构成本次导入的行标识，用于重复提交判定与后续查询。
- 服务端按清单顺序逐行受理：成功行逐笔登记为该订单的一笔收款并返回收款标识，登记后订单已收/未收金额与状态遵循单笔收款规则（不得超过未收金额，收满时回到 `settled`）。
- 同一批次内两条记录使用相同订单标识时，后一条不得覆盖前一条，按位置记为重复被拒（`duplicate_order`），与前一条最终受理成功与否无关。
- 逐行业务拒绝可区分且互不影响，被拒行不产生收款、不改变订单状态：订单不存在或跨租户（`order_not_found`，不泄漏对象是否存在）、金额非法（`invalid_amount`）、超过未收金额（`exceeds_outstanding`）、同批次重复订单（`duplicate_order`）、同一清单内行内序号重复（`line_no_taken`）。业务拒绝与内部错误严格区分：拒绝随逐行结果返回（200），内部错误返回 5xx，绝不混为一谈。
- 原子性：每一行在独立事务内“登记收款 + 落批次结果”原子完成，不存在半行生效的收款；批内某行被拒不影响其他行受理。只有未被冲正的收款合计计入已收金额，已收 + 未收恒等于订单金额。
- 幂等：同一份清单整体重复提交、或同一行标识再次提交时，已成功的行不重复登记、不重复扣减已收金额，逐行结果与首次一致（收款标识稳定返回）；同一标识携带不同金额（或订单）再次提交视为冲突（`identifier_conflict`），必须拒绝且既有状态保持不变。
- 中断续跑：服务中断后用同一批次号重新提交，已落库的行按首次结果回放、不重复受理，未落库的行继续受理，最终结果与一次连续跑完一致；续跑过程中已收与未收金额之和始终等于订单金额。
- 跨租户：用其他租户请求头提交本租户订单的收款时，这些行一律按 `order_not_found` 处理，不泄漏订单是否存在；同一批次中其他租户自己的行不受影响。
- 批量登记产生的收款与单笔登记完全同源，可使用既有冲正接口按返回的 `payment_id` 点名冲正。
