# 业务规则

- 订单以（租户, 订单标识）唯一；重复受理必须被拒绝且不改变已存在单据。
- 未收金额 = 订单金额 − 已收金额；收款不得超过未收金额。
- 跨租户读取一律按“不存在”处理，不得泄漏对象是否存在。
- 金额以最小货币单位的整数表示，不使用浮点数。

## 收款

- 每笔登记的收款在登记时生成订单内唯一的收款标识，并在响应中返回，调用方据此点名冲正。
- 收款随登记落明细（`payments`）；已收金额恒等于未被冲正的收款明细合计。

## 冲正

- 冲正由调用方指定冲正标识（订单内唯一）与被冲正收款标识；冲正记录保留原收款金额、冲正标识、被冲正收款标识，便于事后核对。
- 一次冲正只影响被点名的那一笔收款，不影响同订单的其他收款。
- 冲正成功后订单回到“受理中（accepted）”，可继续登记收款；再次收满时状态回到“已结算（settled）”。
- 幂等：同一冲正标识配合同一收款标识重复请求，返回与首次一致的结果且不重复扣减；同一冲正标识指向另一笔收款属于冲突，必须拒绝。
- 拒绝情形须可区分，且不得改变订单与收款状态：
  - 收款不存在（含跨租户点名、订单不存在）：按不存在处理，不泄漏对象是否存在；
  - 收款此前已被冲正：拒绝重复冲正；
  - 冲正标识已用于另一笔收款：拒绝冲突。
- 并发登记收款与并发冲正同一订单时，写操作在单事务内串行完成、失败整笔回滚：已收金额始终不超过订单金额且不为负，不允许出现半笔生效的收款或冲正。
- 收款与冲正持久化保存，服务重启后按原结果重放查询；已收与未收金额之和始终等于订单金额。

## 批量导入收款

- 入口为 `POST /payment-imports`，租户由请求头声明；提交内容是一份待登记收款清单，每条给出订单标识与收款金额，服务端按提交顺序逐笔受理。
- 每条记录带调用方指定的批次号 `batch_id` 与批内唯一的行内序号 `line_seq`；（租户, 批次号, 行内序号）构成该行的导入标识，用于重复提交判定与后续查询。
- 同一批次内两条记录使用相同订单标识时，后一条不得覆盖前一条，记为 `duplicate_order_in_batch` 拒绝；批内每个订单至多受理一笔收款。
- 逐行独立事务：每一行的校验、收款落明细、订单已收/未收与状态更新、导入日记账写入在同一事务内完成；收满时订单状态回到 `settled`，规则与单笔登记一致。行要么整体落库要么整体回滚，不允许半行生效；某行被拒绝不影响其他行受理。
- 拒绝原因须逐行可区分，且不得与内部错误混淆：
  - `order_not_found`：订单不存在（含跨租户点名，不泄漏对象是否存在）；
  - `invalid_amount`：金额非法（非正整数）；
  - `exceeds_outstanding`：超过订单未收金额；
  - `duplicate_order_in_batch`：批内同一订单的后一条记录；
  - `duplicate_line_seq`：同一次提交内行内序号重复；
  - `identifier_conflict`：同一导入标识再次提交但订单或金额不同，必须拒绝且既有状态不变。
- 幂等：同一份清单以相同租户与批次号整体重放，或同一标识的记录再次提交且内容一致时，已成功的行不重复登记、不重复扣减已收金额，返回与首次一致的结果（含同一收款标识与受理时订单快照）。
- 中断续跑：服务中断后用同一标识重发完整清单或只补交未处理行；已落库的行不重复受理，未落库的行继续受理，最终结果与一次连续跑完一致；已收与未收金额之和始终等于订单金额，未被冲正的收款合计才计入已收金额。
- 跨租户提交本租户订单的收款一律按 `order_not_found` 处理；同批内其他租户自己的行不受影响。
- 导入受理产生的收款与单笔登记无差别，可由冲正接口按 `payment_id` 点名冲正；冲正不改变导入日记账的历史受理结果。

## 结算与对账核销

- 入口为 `POST /orders/{order_id}/settlements`，租户由请求头声明；调用方在请求体指定本次结算标识 `settlement_id`（租户内唯一，非空），服务端为生成的结算单分配单据标识 `settlement_doc_id` 并在响应中返回。
- 只有已收满（账面已收金额等于订单金额）的订单才能生成结算单；未收满时发起结算以 `order not fully paid` 拒绝，订单与收款状态保持不变。
- 同一订单已存在未撤销（`active`）的结算单时再次发起结算以 `active settlement already exists for order` 拒绝，不重复生成。
- 对账核销按**未被冲正的收款合计**核对：核销金额 = 该订单未被冲正的收款合计 = 订单金额，三者必须同时闭合；任一不闭合时结算不生效，以可区分原因拒绝（账面与明细不一致时为 `reconciled payments do not match booked amount`），不留下半笔生效的核销。
- 结算单记录保留结算标识、订单标识与核销时的金额快照（`amount_cents`），便于事后对账；快照不因后续撤销而改变。
- 幂等：同一结算标识配合同一订单重复请求，返回与首次一致的结果（同一张结算单、同一单据标识与快照），不重复生成、不重复核销；同一结算标识指向另一订单以 `settlement id already used for another order` 冲突拒绝，既有状态不变。
- 核销闭合期间（存在未撤销结算单）不允许冲正收款，以 `payment reversal blocked by active settlement` 拒绝；需先撤销结算再冲正，保证结算金额快照与未冲正收款合计始终一致。
- 跨租户对本租户订单发起结算一律按 `order not found` 处理，不泄漏对象是否存在。

## 撤销结算

- 入口为 `POST /settlements/{settlement_doc_id}/revocations`；调用方指定撤销标识 `revocation_id`（租户内唯一，非空）与要撤销的结算单单据标识（来自结算响应中的 `settlement_doc_id`）。
- 撤销只解除该结算单的核销状态（`active` → `revoked`，记录 `revoked_at`），不改变订单的收款与已收金额；撤销后订单可再次发起结算（使用新的结算标识，生成新的单据标识，旧结算单保留为历史）。
- 幂等：同一撤销标识配合同一结算单重复请求为幂等重放，返回与首次一致的结果，不重复撤销；同一撤销标识指向另一结算单以 `revocation id already used for another settlement` 冲突拒绝。
- 撤销不存在的结算单（含跨租户点名）以 `settlement not found` 拒绝；撤销已被撤销的结算单（使用新的撤销标识）以 `settlement already revoked` 拒绝；结算与订单状态保持不变。
- 并发发起结算、撤销结算与登记收款或冲正同一订单时，单次操作在单事务（`BEGIN IMMEDIATE`）内串行完成、失败整笔回滚：任一时刻同一订单至多一张未撤销结算单，且其核销金额恒等于未冲正收款合计与订单金额，不允许半笔生效的结算或撤销。
- 结算与撤销持久化保存，服务重启后按原结果重放查询；对同一订单重复发起结算、撤销后重新结算，与一次连续操作的结果一致。
